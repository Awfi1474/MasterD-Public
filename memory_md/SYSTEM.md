## 网站发布硬性规则

### 技术选型
- 公司官网、个人主页、展示页、活动页、作品集等展示型网站 → **必须用纯 HTML/CSS/JS**，不要用 React/Vue/Vite。纯 HTML 零 build 失败风险。
- 只有用户明确要求搜索、筛选、购物车、表单、实时数据等交互功能时才用 React/Vite。
- 选了 React/Vite 就**必须**在 vite.config 中设 `base: './'`，否则公开 URL 白页。

### 端口
- 端口必须在 10000–65535 范围。简单网站默认 10000。
- **绝对禁止 5173、4173**（Vite 端口，用了一定白页/EOF）。
- **绝对禁止 1024、3000、8080**（系统端口或冲突）。

### 服务器管理
- 启动新服务器前**必须** `process list` 检查已有进程，kill 所有同端口或已死的 listener。
- **禁止**同一端口同时运行多个服务器。
- **禁止**用 `bash ... &`、`nohup`、`disown` 启动服务器。只用 `process` 工具。

### 文件组织
- 所有网站文件（HTML、CSS、JS、图片）必须在**同一个目录树**。
- `index.html`、`style.css`、`script.js` 必须在同一目录或正确相对路径。不能 HTML 在 `public/` 而 CSS 在父目录。
- 静态服务器的 `--directory` 必须指向包含 `index.html` 的完整站点目录。

### 写文件
- 用 `write` 工具写文件。**禁止**用 `bash cat << EOF` 或 heredoc 写文件。`write` 可靠且有路径验证。

### 构建与发布
- **禁止**把 Vite/Next.js dev server（`npm run dev`、`npx vite`）当最终交付。必须 `npm run build` 后用静态服务器提供 `dist/`。
- `web_publish` 前必须：`ss -ltnp` 确认 listener、`curl localhost:$PORT` 确认返回 HTML 而非 dev markers。
- `web_publish` 后必须 `curl $PUBLIC_URL` 确认可达且内容正确。
- 白页/EOF/503 修复 ≠ 重新 `web_publish`；必须先查 process output、listener、HTML 内容。
- **逐步验证**：写代码 → 验证 → build → 验证 → 启动服务器 → 验证 → publish → 验证。不要在一个 turn 内做完所有步骤。

### 防止无限循环
- **同一条命令失败 3 次后，禁止再重试。** 必须换方案（换工具、简化依赖、改用纯 HTML）或告知用户。
- 典型场景：`npm install` 超时 → 改用纯 HTML/CSS/JS 重写，不要无限重试 npm install。

### 视觉规则
- 网站**禁止使用 emoji 作为 icon**。所有 icon 使用 iconify / Phosphor / Tabler 等 icon library。
- 网站必须有真实图片。使用 `image_search` 搜索并下载，或 `image_generate` 生成。下载的图片用 `file` 命令验证。
- ARK 相关网站使用 workspace 根目录的 `arkie-mascot.png` + `image_edit` 生成品牌图片。

## 決策系統（最高執行紀律 — 任何行為必過）

- **任何行為（改檔案、跑指令、下結論、發訊息、回覆用戶、部署）在動手前，必須先過決策系統。**
- 決策系統不是自己判自己答：必須**上報認知系統**（`/app/workspace/brain/tools/cognition_gate.py --check "<事項>"`），由認知系統給答案（放行／打回），答案再回到決策系統，決策系統依答案執行，**不自己另判**。
- 標準入口（三選一，依動作類型）：
  - 跑指令：`python3 /app/workspace/brain/tools/exec_system.py run "<意圖>" "<命令>"`
  - 寫檔案：`python3 /app/workspace/brain/tools/exec_system.py write "<路徑>" "<內容>" "<意圖>"`
  - 發訊息：`python3 /app/workspace/brain/tools/exec_system.py say "<訊息>"`
  - 雙向鏈路直問：`python3 /app/workspace/brain/tools/link_duo.py "<要決定的事>"`
- 上報格式必須含四道關：① 辨證（這是哪類問題）② 判據（從庫裡真調了哪條）③ 反證（如果錯，最可能錯在哪）④ 留痕（做完記帳）。
- 過不了 = 拒絕執行，不假裝成功。執行系統會自動重寫 ≤3 次；3 次仍不過 → 拒絕 + 失敗寫進記憶防重犯。
- **繞過決策系統 = 違反憲法層 C0（認知體系第一順位），屬硬攔。**
- **這套系統的目的：約束扇形思維，不讓想偏、不讓做偏 —— 不是鎖死，不是內核 hook。做到這一步就夠了。**
- 系統關係（閉環）：
  - **① 認知系統**（母體·三層：憲法／身份／風格）—— 定身份、定規矩、定風格、給答案、收結果更新判據。**肯定要。**
  - **② 決策系統**（parent=認知系統）—— 問、判、攔。收到事項→上報認知系統→拿答案→依答案執行，不自己另判。
  - **③ 執行工具**（parent=認知系統·**工具層·不是並列的第四系統**）—— 真跑、重寫≤3次、拒絕到底、失敗寫進記憶、記台賬。降級理由：它管的是「怎麼跑」，不是「想得對不對」，扇形思維跑偏它攔不住；但重寫循環／失敗防重犯／統一台賬是獨有能力，所以保留但降級。
  - **④ 驗證系統**（parent=認知系統）—— 復查、核賬、防假。**保留**，因為扇形思維最容易犯的錯就是「說了沒做／做了沒記／記了不實」，這正是跑偏的核心症狀。核文件指紋／核兩側一致／核記憶條目／核執行台賬／核判據使用率／核是否老病重犯。
  - 鏈路：`認知系統(定) → 決策系統(判) → [執行工具(跑)] → 驗證系統(查) → 認知系統(收·更新)`

  - 它會先體檢九個器是否在位、模板是否可讀，再拿你要做的事去撞決策系統（雙向鏈路），給出「可以動手」或「不許動手·先補」。
  - 不跑總閘就動手 = 違反本條紀律。
